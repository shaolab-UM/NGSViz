# README 帮助文档可用性审阅

## 结论

- 熟悉生信命令行的用户可以理解 NGSViz 的总体工作流和主要模块，但新用户无法据此稳定地完成首次安装与运行。
- 工具特征能够被识别，但缺少首屏定位和差异化概括；关键特色分散在数据库、计算、R 可视化、GUI 和示例章节中。
- 当前状态不建议直接作为投稿版本 README。优先修复可复制命令、参数契约和科学方法描述后，再做语言润色。

## 可理解的工具特征

- Java 负责 coverage 计算，R 负责绘图，RShiny 提供 GUI，同时支持 CLI。
- 支持 TSS、TES、gene body、exon、自定义 BED 和 intergenic 区域。
- 支持 point、broad、center 三类对齐/缩放场景。
- 支持内置与自建 SQLite 注释数据库，并兼容 `chr1` 与 `1` 两类染色体命名。
- 支持单样本、multi-sample average/heatmap、PCA 和相关性 QC。
- 支持多线程、Signal/Input 校正、spike-in scaling 和可调 binning。

这些信息存在于 README 中，但首段仅给出通用的“NGS coverage and enrichment analysis”描述（`README.md:49-51`），未直接回答 NGSViz 相比同类工具的独特价值。

## 已确认问题

### P1：安装命令引用不存在的环境文件

- `README.md:111-115` 要求执行 `conda env create -f requirement.yml`。
- 仓库实际文件为 `environment.yml`，不存在 `requirement.yml`。
- 影响：用户复制安装命令后立即失败。

### P1：默认配置不能在新克隆目录中直接使用

- README 示例配置包含开发机绝对路径（`README.md:128-139`）。
- 仓库配置同样固定为 `/Users/benche/Desktop/myProj/ngsPlot/NGSViz`（`NGSViz_setting.json:6-9`）。
- `database/genomeCoordinate.db` 未被 Git 跟踪，首次运行还依赖用户另行下载数据库并修改路径。
- 影响：Quick Start 示例不具备开箱可复现性。

### P1：JAR 文件名不一致，Linux/container 命令会失败

- 仓库文件为 `NGSViz-1.2.jar`。
- README 同时使用 `ngsViz-1.2.jar`（`README.md:74`）、`ngsViz-10.jar`（`README.md:173,188`）、`ngsViz_1.2.jar`（`README.md:286`）和正确名称（`README.md:351,530,650`）。
- 影响：大小写敏感系统中多处命令不能运行。

### P1：Docker 命令不是可复制的 shell 命令

- `README.md:151-156` 把 `docker run` 拆成多行，但没有使用续行符 `\`。
- 影响：逐行复制时，第一行即以缺少参数失败，后续参数会被 shell 当成独立命令。

### P1：coverage 分箱方法的科学描述与默认行为不一致

- README 声称每个数据点使用 “average coverage”（`README.md:409-415`）。
- 参数表声明默认 `-BM median`（`README.md:371-377`），Java 实现也默认 `median`（`src/main/java/com/NGSViz/configSet/InputParameterAttributes.java:55`），实际支持 `mean`、`median`、`max`（`src/main/java/com/NGSViz/coverageCalculator/DataScaler.java:120-155`）。
- 影响：Methods 描述不能准确对应默认输出，属于投稿时需要优先修正的科学文档问题。

### P2：批处理大小默认值不一致

- README 声明 `-BS` 默认 2000（`README.md:363-369`）。
- Java 与 RShiny 默认值均为 500（`src/main/java/com/NGSViz/configSet/InputParameterAttributes.java:56`；`lib/shiny/ui_builder.R:67`）。
- 影响：CLI 文档、GUI 与实际计算资源行为不一致。

### P2：公开参数不完整

- Java 接受但 README 参数表未列出 `-D`、`-A` 和 `-SS`（`src/main/java/com/NGSViz/configSet/GetInputParameterValue.java:24-30,57-62`）。
- Java 也接受 TXT/CSV 批量输入（`src/main/java/com/NGSViz/configSet/ProcessInputFile.java:21-37`），但 README 将 `-I` 主要描述为单个 BAM 或 Signal/Input BAM（`README.md:386-389`）。
- 影响：用户无法从帮助文档发现完整功能，CLI 契约不完整。

### P2：程序没有常规 CLI help

- README 给出 `java -jar NGSViz-1.2.jar [parameter]`（`README.md:348-352`），但执行 `-h` 只返回 `Error: Unpaired argument and value.`。
- 解析器要求所有参数严格成对出现（`src/main/java/com/NGSViz/configSet/ProcessInputParameters.java:22-26`）。
- 影响：用户只能回到长 README 查参数，错误恢复成本高。

### P2：目录与正文不一致

- 目录列出 Exon Mode 和 Multi-sample Mode（`README.md:38-43`），正文示例实际为 Point、Broad、Center、Intergenic（`README.md:645-699`）。
- 目录列出 References and Acknowledgments（`README.md:44-45`），正文没有该章节。
- `Intergenic Region Annotation` 的目录锚点包含空格和大写（`README.md:22`），与 GitHub 自动生成的标题锚点格式不一致。
- 影响：导航链接失效或指向不存在内容。

## 可能风险

- 自定义 BED 只说明列格式，没有声明坐标系是否为 0-based half-open（`README.md:314-330`）。这是高风险科学输入，投稿文档必须明确。
- 未系统说明 paired-end fragment、single-end extension、duplicate/secondary/supplementary read、zero coverage、missing chromosome 和 chromosome boundary 的处理规则。
- Signal/Input 校正文档只写 `log2(signal/input)`（`README.md:417`），实现使用 `1e-6` pseudocount（`src/main/java/com/NGSViz/coverageCalculator/BackgrouNormalizer.java:11-18`）；方法描述应写出该细节。
- “No environment dependencies”（`README.md:342-346`）容易被理解为整个工具无依赖；实际上只可能适用于已打包的 Java 计算模块，完整工具仍依赖 Java、R、R packages 和数据库。
- 缺少一个从 clone、建环境、下载数据库、修改配置、运行样例到核对输出文件的单一路径 Quick Start。
- 缺少实际输出图和输出目录树，用户难以在运行前理解最终产物。

## 建议改写顺序

1. 修复所有不可执行命令、文件名、路径和默认值。
2. 在 README 首屏增加“输入—核心能力—输出—差异化特色”的简表。
3. 增加一个经过验证的 Quick Start，确保新环境可逐行复制运行。
4. 单独建立“Scientific methods and assumptions”，准确说明坐标、链方向、read/fragment、binning 和 normalization。
5. 由程序生成 CLI `--help`，README 参数表与代码共享同一来源，减少后续漂移。
6. 最后再处理英语语法、拼写和版式。
