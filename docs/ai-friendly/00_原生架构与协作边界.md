# ngsViz 原生 AI-friendly 架构与协作边界

## 模块边界

- Java 是计算模块。它读取 BAM/BAI、参考坐标数据库与 CLI 参数，生成覆盖矩阵、read count CSV 和 plot-setting JSON。
- R 是可视化模块。它读取计算阶段生成的 plot-setting JSON，并按其中声明的 CSV 路径和绘图参数生成图片。
- Java 与 R 是两个独立 CLI，二者不互相启动。Java 完成计算后退出；R 由用户或外部编排器另行调用。
- R 可在计算完成后的任意时间独立调用，不要求与 Java 处于同一进程、同一会话或连续执行。

## 外部编排边界

- Codex Skill 是项目外部的编排规则，不是项目运行时，不进入 Java/R 依赖、发布包或运行环境。
- AI-friendly 工作流不使用 Python、MCP、Web API。编排仅调用项目既有的 Java CLI、R CLI 和本地文件。
- Java 每次只计算一个 sample。一次 AI-friendly Java 调用只传入一个待计算 sample 及其可选 background/input BAM。
- AI 多样本模式由 Codex 顺序启动多个 Java 进程，每个进程处理一个 sample，并分别检查退出状态和输出。
- 多样本计算默认顺序执行，不在单个 Java 进程内增加 AI 专用批处理层，也不由 R 反向触发计算。

## 文件契约

- 现有 `*_NGSViz_plotSetting.json` 是 Java 输出、R 输入的唯一文件契约，也是 R 可视化 CLI 的唯一计算结果入口。
- plot-setting JSON 声明 `OutputFile` 中的 coverage matrix CSV 和 read count CSV 路径，同时携带绘图参数、输出参数、拆分参数、主题参数与版本信息。
- CSV 是契约引用的数据文件，不建立绕过 plot-setting JSON 的第二套 Java/R 入口。
- 本次升级不得引入 Python 中间文件、MCP 消息、Web API 请求或隐式进程通信。
- R 的延迟调用以 plot-setting JSON 及其引用文件仍然可访问为前提；计算与绘图之间不存在进程级状态依赖。

## 兼容性与变更范围

- 旧 CLI 必须向后兼容：现有参数名、参数类型、默认值、调用方式、输出命名与退出行为不得因 AI-friendly 编排被无意破坏。
- AI-friendly 的单 sample 调用约束属于外部编排边界，不授权删除旧 CLI 已有能力或改变旧命令的解释方式。
- 科学行为不在本次升级范围。不得改变坐标约定、链方向、TSS/TES 定义、gene-body scaling、binning、coverage/counting、normalization 或缺失值处理。
- Phase 0 只冻结架构、协作边界与可复核基线，不修改 Java/R 代码。

## 标准执行关系

```text
Codex Skill（外部编排）
  ├─ sample 1: 启动一次 Java CLI ─┐
  ├─ sample 2: 启动一次 Java CLI ─┼─ 顺序执行，分别生成 plot-setting JSON 与 CSV
  └─ sample N: 启动一次 Java CLI ─┘

任意后续时间：
用户或 Codex ──启动 R CLI──> 读取 plot-setting JSON ──> 读取其引用的 CSV ──> 输出图片
```
