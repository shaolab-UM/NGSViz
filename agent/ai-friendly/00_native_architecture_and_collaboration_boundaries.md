# ngsViz Native AI-Friendly Architecture and Collaboration Boundaries

## Module boundaries

- Java is the computation module. It reads BAM/BAI files, the reference-coordinate database, and a `ComputeRequest` normalized from either legacy CLI flags or `compute_request.json`. It produces coverage matrices, read-count CSV files, and plot-setting JSON files.
- R is the visualization module. It reads the plot-setting JSON generated by Java and produces figures from the referenced CSV files and plotting parameters.
- Java and R are independent CLIs and must never launch each other. Java exits after computation; the user or an external orchestrator invokes R separately.
- R may be invoked at any later time. It does not need to share a process, session, or uninterrupted workflow with Java.

## External orchestration boundaries

- The Codex Skill defines orchestration outside the project. It is not part of the runtime, Java/R dependencies, release archive, or execution environment.
- The AI-friendly workflow must not introduce Python, MCP, or a Web API. Orchestration may call only the native Java CLI, R CLI, and local files.
- Codex must write a single-sample `compute_request.json` before calling `run-compute --request <path>` or `validate-compute --request <path>`. It must not construct a legacy-flags command containing all compute parameters.
- The JSON request path is the only compute-parameter input for AI-friendly Java commands. Legacy flags such as `-G`, `-R`, `-I`, and `-O` must not be appended or used to override JSON fields.
- `-J <yaml>`, YAML configuration, and YAML loaders are forbidden for AI parameters. The existing `-J` placeholder is not part of the new interface.
- Each Java invocation computes exactly one signal sample and, optionally, one background/input BAM.
- Codex implements multi-sample computation by launching Java processes sequentially, checking each exit status and output before starting the next process.
- Multi-sample computation must not add an AI-only batch layer inside Java, and R must never trigger computation.

## File contract

- Existing `*_NGSViz_plotSetting.json` files are the only Java-output/R-input contract and the only computation-result entry point accepted by the R CLI.
- A plot-setting JSON references coverage-matrix and read-count CSV files through `OutputFile` and carries plot, output, split, theme, and version parameters.
- CSV files are data files referenced by that contract; they must not become a second Java/R interface that bypasses plot-setting JSON.
- This architecture must not introduce Python intermediates, MCP messages, Web API requests, or implicit inter-process communication.
- Deferred visualization requires the plot-setting JSON and all referenced files to remain accessible. No process-level state is shared between computation and plotting.

## Compatibility and change scope

- The legacy CLI remains backward compatible: existing option names, types, defaults, invocation forms, output names, and exit behavior must not be changed unintentionally.
- Legacy flags and `compute_request.json` are mutually exclusive inputs. Both normalize to the same `ComputeRequest`, pass through the same validation boundary, and invoke the same `MainCalculator`; scientific computation must not be duplicated.
- Legacy compatibility covers actual compute parameters. The `-J` placeholder, which stores a path but loads no configuration, is not an AI configuration contract and must not become a YAML runtime.
- The external single-sample constraint does not authorize removal or reinterpretation of legacy CLI capabilities.
- Scientific behavior is outside this change scope. Coordinate conventions, strand direction, TSS/TES definitions, gene-body scaling, binning, coverage/counting, normalization, and missing-value handling must remain unchanged.

## Standard execution relationship

```text
Codex Skill (external orchestration)
  |-- write sample 1 compute_request.json -> launch Java CLI once --+
  |-- write sample 2 compute_request.json -> launch Java CLI once --+-- sequential
  `-- write sample N compute_request.json -> launch Java CLI once --+

Inside Java:

legacy CLI flags ---------+
                          +-> ComputeRequest -> validate -> MainCalculator
compute_request.json -----+

At any later time:
User or Codex -> launch R CLI -> read plot-setting JSON -> read referenced CSV -> write figures
```
